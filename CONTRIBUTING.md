# Contributing

> `FINAL_FROZEN_PUBLICATION_CANDIDATE / ISSUE_FIRST_THEN_PULL_REQUEST / NOT_PUBLISHED`

```text
CONTRIBUTION_INTAKE_POLICY = ISSUE_FIRST_THEN_PULL_REQUEST
CLA_AT_INITIAL_LAUNCH = NO
DCO_AT_INITIAL_LAUNCH = NO
DIRECT_MAIN_PUSH = PROHIBITED
```

Before a non-trivial Pull Request, open an Issue or Discussion and wait for maintainer scope confirmation. Trivial documentation corrections may be submitted directly as a Pull Request. Work must use a fork or working branch; do not push directly to `main`.

Every Pull Request must reference its Issue or explain why it is a trivial documentation correction, describe tests, identify affected license paths, and confirm that it contains no secrets, Credential material, personal data, customer data, production snapshots, or third-party restricted content.

No CLA or DCO is required at initial launch. This does not waive the requirement that a contributor must have the right to submit the material under the applicable path-specific license.

```text
contribution != adoption
contribution != Canonical Authority
review != approval
merge != release
```

Canonical, Character data, Security routing, License boundaries, and public release controls remain maintainer-reviewed sensitive areas.
