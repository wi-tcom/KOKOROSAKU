はじめて使う

Characterを選び、5章で作成し、AI プラットフォームで応答を確かめて、Workspaceへ保存します。

一覧が空でも、保存済みworkspace/charactersからCharacter Libraryを復元できます。

サンプルCharacterを読み込む

インストーラー版には、サンプル Character が 3 体入っています。「01 キャラクターを選択する」の「サンプルを読み込む」を押すと、ほかのパックと同じ確認を通ってから一覧に入ります。インストールせずに試す ZIP 版には、このボタンはありません。サンプルは評価・動作確認・学習のために使えます。再配布・改変や転用・商用利用はできません（同梱の LICENSE.md、LicenseRef-WIT-Sample-1.0）。

Workspaceへの保存とCanonical採択は別です。

編集画面から 03 へ進む

編集画面の「AIプラットフォームで動作確認」を押すと、いま編集している Character を「03 AI プラットフォームでキャラクターを動作」へ渡します。未保存の変更があるときは、先に「この内容で保存する」と同じ保存を行うか確認します（キャンセルすると編集画面に留まります）。外部AIへ貼り付ける文は 03 で作ります。編集画面の出力タブには、character.yaml、Character File（署名やパックを作るときの元になる JSON）、試験記録があります。

locator のずれを修復して読み込む

個別インポートで「CONFORMANCE_LOCATOR_MISMATCH」（locator が要件とずれている）と表示され、「locator を修復して読み込む」ボタンが出ることがあります。2026-09-22 より前に編集画面で保存した Character に起きる既知の症状です。ボタンは requirement_id から参照位置（locator）を計算し直すだけで本文は変えず、修復後は新しい revision として一覧に入り、詳細の「locator 修復」行に修復前後の digest が残ります。手元の JSON をまとめて直すには node tools/v1/relocate-locators.mjs <ファイルか フォルダ> で差分を確認し（既定は dry-run）、--out <出力先> で書き出します。署名付きパックの中身は修復しません。
